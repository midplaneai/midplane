One YAML file, `midplane.yaml`, named with `--config`. Relative paths in it
are relative to the file. Secrets never appear inline: a DSN, the mask salt,
the identity and the enrollment token each name an environment variable or a
file, so the config itself can be committed.

```yaml
dsn: { env: DSN_MAIN }            # an environment variable
dsn: { file: /run/secrets/dsn }   # or a file, read once at start
```

Unknown keys are errors, and so is anything that doesn't validate: the
gateway won't start on a config it can't fully read.

## Both modes

| Key | Default | What |
| --- | --- | --- |
| `listen.host` | `127.0.0.1` | Interface to listen on. Anything but loopback requires `tls`. `0.0.0.0` or `::` also requires `public_urls` |
| `listen.port` | `7433` | |
| `listen.allowed_hosts` | `[]` | Up to eight more host names the `Host` header may carry, for a proxy that rewrites it: a name, or an IPv6 address in brackets. Not token audiences ([hosted agents](/gateway/hosted-agents)) |
| `public_urls` | none | Up to eight base URLs agents reach the gateway at, with no credentials, query or fragment: `https://…`, or `http://` on your computer (`localhost`, a name under `.localhost`, `127.0.0.1` or `[::1]`). Midplane Cloud registers no other http URL, so a linked gateway that lists one can't join a project. Each `<url>/mcp` is a token audience. Without them, the listener's own URL |
| `public_url` | none | Shorthand for one; not with `public_urls` |
| `tls.cert_file`, `tls.key_file` | none | PEM files; HTTPS on the listener. (`0.23.0+`) Read again every 10 minutes: a replacement whose key matches, that is in date and covers the same public URL hosts is served to new connections without a restart |
| `tls.acme` | none | (`0.23.0+`) A certificate the gateway gets and renews itself, from Let's Encrypt; not with `cert_file` and `key_file` ([automatic certificates](#automatic-certificates)) |
| `tls.acme.http_port` | `7480` | Where the challenge listener binds, on every interface. The server's port 80 must reach it; not `listen.port` |
| `tls.acme.directory_url` | Let's Encrypt | Another ACME directory, such as Let's Encrypt's staging (`https://acme-staging-v02.api.letsencrypt.org/directory`), whose certificates agents don't trust. https, or http on loopback |
| `audit.file` | required | The audit log, a SQLite file ([audit](/audit)). Local processes may share one; give each linked gateway its own |
| `audit.retention_days` | `30` | Days to keep each event after Midplane Cloud has it (in local mode, after it is recorded; an event a linked gateway left unsent, after the file is opened in local mode), at most 3650. An event the cloud hasn't acked is kept however old. `0` keeps everything |
| `mask_salt` | none | A secret source for the salt that keys `consistent-hash` masks: at least 32 characters, the same on every instance ([secrets](/gateway/secrets)). Required once a policy has masks |
| `limits.max_rows` | `1000` | Rows returned per query, at most 1,000,000. A read stops at the cap and says it was truncated |
| `limits.max_bytes` | `1048576` | Bytes returned per query, from 1 KiB to 256 MiB |
| `databases.<id>.dsn` | required | A secret source for the connection string, for at least one database. The id starts with a lowercase letter and has up to 32 lowercase letters, digits, `-` or `_` (`main`, `billing-eu`) |

## Automatic certificates

(`0.23.0+`) With `tls.acme`, the gateway gets its certificate from Let's
Encrypt for the host of its one https public URL, and keeps it current:

```yaml
listen: { host: 0.0.0.0, port: 7433 }
public_urls: [https://midplane.example.com]
tls: { acme: {} }
```

- **Before it listens**, it uses the certificate it kept, if that covers the
  host and has more than 30 days left, or gets a new one. If Let's Encrypt
  refuses and the kept certificate still covers the host and is in date, the
  gateway serves it, logs `certificate renewal failed`, and renews it at the
  next check. With no certificate it can serve, the gateway exits, its last
  log line saying why with `acme_type` and `acme_detail` ([troubleshooting](/troubleshooting#the-gateway-does-not-connect)).
- **Every 12 hours** it renews a certificate with 30 days or fewer left, and
  serves the new one to new connections without a restart. A renewal that
  fails logs `certificate renewal failed` and is tried at the next check; the
  current certificate is served meanwhile.
- **Let's Encrypt checks the host** with an HTTP-01 challenge: it fetches a
  token from port 80 of the host, which must reach `http_port` (in Docker,
  `-p 80:7480`). The listener there answers a token pending right now and
  nothing else: every other request, `/mcp` included, gets an empty `404`,
  so no agent's token is read in the clear.
- **It keeps** the certificate, its key and the account's key in `acme/`
  beside the config, closed to other users. Keep the folder: Let's Encrypt
  issues at most five certificates for the same host a week.

The host must be a name, not an IP address, and must be the only https
host in `public_urls`: a tunnel's or proxy's URL leads Let's Encrypt
somewhere else. Getting a certificate agrees to Let's Encrypt's [subscriber
agreement](https://letsencrypt.org/repository/). Setup with `--acme` (`midplane
setup --url https://… --acme`) writes `tls: { acme: {} }` and gets the first
certificate before it joins the project.

## Behind the relay

With `relay`, agents reach a linked gateway through Midplane's relay, at its
Midplane URL, and the gateway only connects out.
`midplane setup --relay`, or setup from environment variables without
`MIDPLANE_URL`, asks Midplane Cloud for its relay and writes:

```yaml
listen: { host: 127.0.0.1, port: 7433 }
relay: { control: relay.eu.midplane.app }
public_urls: [https://gw-7hq2m4xd.eu.midplane.app]
tls: { acme: {} }
```

- **`relay.control`** is the relay's name, `relay.` and the relay domain.
  The gateway keeps 4 connections open to it on port 443, authenticated with
  its link token, and takes agents' connections over them.
- **`public_urls`** holds one URL, the gateway's Midplane URL:
  `https://gw-` and 8 characters, on the relay domain, with no port or path.
  It gets one only when it joins a project, and it is never given to another
  gateway, even after this one is revoked.
- **`tls.acme`** is required, without `http_port`: the gateway gets its
  certificate from Let's Encrypt through the relay, which forwards the check
  of port 80 to it, so it binds no port for it. `directory_url` may name
  another ACME directory.
- **`listen.host`** must be loopback: the listener is for health checks, and
  agents come through the relay.

Each of these is checked at start, and a config that breaks one is refused
by its key. A config with `relay` in local mode is refused too. What the
relay sees, and what it can't, is in [security](/security#the-relay).

Two more rules the config can't check:

- **It needs a disk.** The gateway keeps its certificate in `acme/` beside
  the config, on its volume, and never in a variable. Without a disk it
  gets a new certificate at every start, and Let's Encrypt issues at most
  five for one name a week.
- **Run at most two copies of it.** The relay holds 8 idle connections per
  gateway, and each copy keeps 4. Each copy orders its own certificate, out
  of the same five a week, and the relay passes Let's Encrypt's check to one of the gateway's connections
  after another until the copy that ordered it answers. For more copies, use
  your own URL ([replicas](/gateway/multiple-gateways#replicas)).

## Local mode only (`midplane local`)

| Key | Default | What |
| --- | --- | --- |
| `project` | `local` | The `project` claim tokens must carry |
| `auth.issuer` | required | The `iss` tokens must carry |
| `auth.public_key_file` | required | A public JWK (or a JWKS) that tokens are verified with; `midplane keygen` writes one |
| `auth.revoked_token_ids` | `[]` | Token ids (`jti`) to refuse |
| `databases.<id>.policy` | `{}` | The database's policy (below). `{}` means nothing is readable |

## Linked mode only (`midplane gateway`)

| Key | Default | What |
| --- | --- | --- |
| `link.cloud_url` | required | Midplane Cloud's URL: https, or http on loopback |
| `link.identity` | required | Where the gateway's identity lives: `{ file: identity.json }`, written at enrollment, or `{ env: VAR }` holding what `midplane enroll` printed ([linked mode](/gateway/linked-mode)) |
| `link.enrollment_token` | none | A secret source for the one-time token from the project's Gateways page; read only until the identity exists |
| `link.bundle_cache` | `bundle.jws` | The newest authentic bundle, enforced again after a restart with the cloud down |
| `link.name` | none | How the dashboard names this gateway, up to 80 characters |
| `relay.control` | none | The relay's name, `relay.<domain>`, such as `relay.eu.midplane.app`: agents reach the gateway through it ([behind the relay](#behind-the-relay)) |

Linked databases have no `policy`: policies come in signed bundles from
Midplane Cloud.

## Setup from environment variables

(`0.24.0+`) `midplane start`, the image's default command, serves the first
of these that exists:

1. `/etc/midplane/midplane.yaml`, a config you mounted.
2. `/var/lib/midplane/midplane.yaml`, the config of a volume set up before.
3. With `MIDPLANE_ENROLLMENT_TOKEN` set, a gateway it sets up in
   `/var/lib/midplane` from the variables below, then serves: behind the
   relay, as `midplane setup --relay` would from its answers, or with
   `MIDPLANE_URL` at that URL, as `midplane setup --acme` would. It joins the
   project first and gets the certificate as it starts, so a token the
   project refuses gets none.

Without any of them, it exits with `no config`. Each variable is read on the
first start only, but for the connection strings:

| Variable | Required | What |
| --- | --- | --- |
| `MIDPLANE_CLOUD_URL` | yes | Midplane Cloud's URL, such as `https://eu.app.midplane.ai` (`--cloud`) |
| `MIDPLANE_ENROLLMENT_TOKEN` | yes, until it has joined | The token from the project's setup page (`--token`) |
| `MIDPLANE_URL` | no | The `https://` URL agents reach the gateway at (`--url`). Its host must be a name: the certificate is automatic (`--acme`). Without it, the gateway is set up [behind the relay](#behind-the-relay) (`--relay`), and a cloud without a relay refuses it |
| `MIDPLANE_DSN_<ID>` | at least one | A database's connection string. The id is `<ID>` lowercased: `MIDPLANE_DSN_SHOP` is `shop`. An id with `-` can't be named this way, as Docker drops such a variable: use an id with `_`. Kept in the environment: the config names the variable (`dsn: { env: MIDPLANE_DSN_SHOP }`), and the gateway reads it at every start |
| `MIDPLANE_PORT` | no | The port the gateway listens on in the container, `7433` by default (`--port`). Behind the relay, on loopback, for health checks |
| `MIDPLANE_ACME_DIRECTORY` | no | Another ACME directory, such as Let's Encrypt's staging (`--acme-directory`) |

Setup's messages are log lines. It checks the variables before it writes
anything: it names at once every one that is missing and every
`MIDPLANE_DSN_*` that is wrong, then the first other value that is wrong,
and never a connection string's value. A failure before the gateway joins
the project removes what it wrote and leaves the token unused. A certificate
it can't get is tried again at each start. A start that fails exits at once,
its error the last log line, and a restart policy starts it again.

Once the volume has a config, a new `MIDPLANE_DSN_*` alone is ignored: add
the database to the config too ([adding
databases](/gateway/multiple-gateways#adding-databases)).

## Commands

Every command needs Node 24.16 or newer. One with a flag it doesn't know
prints the usage.

| Command | What |
| --- | --- |
| `midplane setup` | Asks for each database's connection string, tests it, writes the gateway's folder and joins the project, then serves it as `midplane gateway` would. Stopped with `Ctrl-C` before it joins, it removes what it wrote and leaves the token unused. Its flags are [below](#setup-flags) |
| `midplane start [--config <file>] [--dir <dir>]` | The image's default command. Serves `--config` (`/etc/midplane/midplane.yaml` by default), else `<dir>/midplane.yaml` (`/var/lib/midplane` by default), else sets up from the environment into `<dir>` and serves ([setup from environment variables](#setup-from-environment-variables)) |
| `midplane gateway --config <file>` | Serves in [linked mode](/gateway/linked-mode) |
| `midplane enroll --config <file> [--out <file>]` | Joins the project once and prints the identity as one line of JSON, or writes it to `--out` with mode 0600 |
| `midplane local --config <file> [--stdio]` | Serves in [local mode](/gateway/local-mode). With `--stdio`, MCP goes over stdin and stdout, with the token in `MIDPLANE_TOKEN` |
| `midplane keygen --out <dir>` | Writes `midplane-signing-key.json` (mode 0600) and `midplane-verify-key.json` in `<dir>` |
| `midplane token --config <file> --key <file> --sub <who>` | Prints a local-mode token, signed with the key `--key` names. `--database <id>` limits it to one database (every one in the config by default), `--access` is `read` (the default) or `write`, and `--ttl` is in seconds (`3600` by default) |
| `midplane audit export`, `midplane audit verify` | Export the audit file, and verify a file or an export ([audit](/audit#export-and-verify)) |
| `midplane --version` | Prints `midplane` and its version |

`enroll` and `keygen` never write over a file.

### Setup flags

| Flag | Default | What |
| --- | --- | --- |
| `--cloud <url>` | required | Midplane Cloud's URL: https, or http on loopback |
| `--token <mpe1_…>` | required | The enrollment token |
| `--database <id>` | none | A database of the project, asked for first. Repeat it for each; `Enter` skips one. Setup then offers to add others |
| `--relay` | off | Sets the gateway up [behind the relay](#behind-the-relay). Not with `--url`, `--acme` or `--tls-dir`. A cloud without a relay refuses it |
| `--url <https://…>` | none | The URL agents reach a server gateway at: https, a host and no path. The gateway listens on every interface, with TLS |
| `--tls-dir <dir>` | `/etc/midplane/tls` | With `--url`: the folder holding the certificate, `tls.crt`, and its key, `tls.key`. Setup checks that the certificate covers the URL's host, is in date and matches its key |
| `--acme` | off | With `--url`: an [automatic certificate](#automatic-certificates), which setup gets before it joins the project, answering Let's Encrypt's check on port 7480. Not with `--tls-dir`. The URL's host must be a name |
| `--acme-directory <url>` | Let's Encrypt | With `--acme` or `--relay`: another ACME directory, https or http on loopback |
| `--port <n>` | `7433` | The port to listen on, 1 to 65535. On loopback (on your computer, or behind the relay), the port asked for must be free, and without one setup takes the first free port from 7433 to 7442 |
| `--dir <dir>` | `gw-` and 8 characters | The gateway's folder. It must not exist, or must be empty but for `lost+found` |
| `--no-start` | off | Exit once set up, instead of serving |

Without `--relay` or `--url`, setup makes a gateway for your computer: on
loopback, at `http://gw-….localhost` and its port, with no TLS.

## The policy

A database's policy, in local mode under `databases.<id>.policy`, in linked
mode authored in the dashboard (which shows it as JSON too). Strict: an
unknown key anywhere refuses the whole policy, never part of it.

```yaml
table_access:
  default: deny                  # deny | read | read_write
  tables:
    public.customers: read       # schema-qualified
    public.notes: read_write
writes:
  row_changes: hold              # allow | hold | deny; INSERT, UPDATE, DELETE, CREATE TABLE [AS]
  schema_changes: deny           # allow | hold | deny; ALTER, DROP, CREATE INDEX
masks:
  public.customers:
    id: none                     # reviewed and left clear
    email: consistent-hash
    phone: { t: partial, keepEnd: 4 }
    created_at: { t: generalize, granularity: month }
labels:
  untrusted_columns:
    public.support_tickets: [body]
  secret_tables: [public.api_keys]
role: agent_readonly             # SET LOCAL ROLE for every statement
limits:
  statement_timeout_ms: 30000
  lock_timeout_ms: 5000
```

| Section | Default | What |
| --- | --- | --- |
| `table_access.default` | `deny` | Access to a table not listed. `information_schema` is always readable, `pg_catalog` never. A partition without its own entry takes its parent's |
| `table_access.tables` | `{}` | `schema.table` → `deny`, `read` or `read_write` |
| `writes.row_changes` | `allow` | `hold` waits for a person's approval (linked mode); while an agent is tainted, `allow` becomes `hold` |
| `writes.schema_changes` | `deny` | Only shape changes are ever allowed: owners, row security, triggers and storage options are refused |
| `masks` | `{}` | `schema.table` → column → rule ([masking](/policies/masking)). In a table with an entry, a column without one is fully redacted until reviewed |
| `labels.untrusted_columns` | `{}` | Columns whose values anyone may have written. Reading one taints the agent's grant |
| `labels.secret_tables` | `[]` | Tables a tainted grant may not touch ([approvals and taint](/policies/approvals-and-taint)) |
| `role` | none | Role every statement runs as (`SET LOCAL ROLE`); the gateway's login role must be a member |
| `limits.statement_timeout_ms` | `30000` | Up to an hour |
| `limits.lock_timeout_ms` | `5000` | Up to an hour |

Whatever the policy says, a statement must be one statement Midplane can
parse and resolve; writes need a `WHERE`; writes hidden inside a `WITH` are
denied; and reads run in read-only transactions.
