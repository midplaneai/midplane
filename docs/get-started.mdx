---
title: "Get started"
description: "From a new Midplane Cloud project to the first query an agent makes through your gateway."
---

You need a Postgres database and its connection string (or Docker, for the
sample one), Node 24.16 or newer, and an MCP client such as Claude Code.

<Steps>
  <Step title="Create a project">
    Midplane Cloud is invite-only for now: [get access](https://midplane.ai/#get-access),
    and we'll email you an invitation. Follow its link to create your account
    at [eu.app.midplane.ai](https://eu.app.midplane.ai), verify your address,
    name your organization and create a project. Its overview opens on **Connect your
    first database**.
  </Step>
  <Step title="Run the gateway">
    Have a connection string at hand for a role the gateway logs in as.
    **Before you start**, in the step, has the SQL for a read-only one
    ([prepare your database](/prepare-database)). No database at hand? Try
    [the sample](#with-the-sample-database) instead.

    **Create enrollment token**, pick **This machine** or **A server
    (Docker)**, and run the command the step shows. `midplane setup` asks for
    each database's connection string, tests it, and names it in Midplane,
    such as `shop`: your name for the database, not its Postgres name. Then it
    joins your project and starts the gateway. The step lists each database
    as the gateway reports it (`shop · reachable · catalog read: 12 tables`),
    and it's done when the gateway enforces the project's policy ([deploy the
    gateway](/gateway/deploy)).
  </Step>
  <Step title="Choose what agents may read">
    A new policy denies everything. **Open `shop`'s policy** from the step and
    set the tables agents may read; setting **Default access** to **Read**
    opens every table the policy doesn't list, including tables created later.
    Review the columns that look like personal data or credentials, then
    **Review and publish**. **Back to setup** returns to the card.
  </Step>
  <Step title="Connect an agent">
    Run the `claude mcp add` command the step shows, then `/mcp` in Claude Code
    and **Authenticate**. Sign in, and choose which databases it may use.
    Another client? See [Cursor](/agents/cursor), [VS Code](/agents/vs-code)
    or [claude.ai](/agents/claude-ai).
  </Step>
  <Step title="Try it">
    Ask your agent one of the questions the step suggests about a table it may
    read, such as "How many rows are in `public.customers`?". The card finishes
    with that query, and every statement shows up in the **Query log**.
  </Step>
</Steps>

Stuck? See [troubleshooting](/troubleshooting).

## With the sample database

No database at hand? On **Run the gateway**, an owner or admin can choose the
**Try with sample data** tab. It creates a second project, **Sample shop**,
with the database `shop` and the sample's policy published: customers' emails
hashed and phones partly hidden, support ticket bodies untrusted, the API keys
secret, and row changes held for approval. The project you started from stays
as it is, for your own database.

In the sample project, **Run the gateway** starts the sample's Postgres with
Docker, then setup on this machine, which runs the gateway on port 7434 so it
can run beside one of your own. When setup asks for `shop`'s connection
string, paste the one the step shows (the password is a public example).
**Choose what agents may read** is already done. When Claude Code signs in,
give it read and write on `shop`, then ask, in order:

1. "List our customers with their emails and plans": emails come back
   hashed, phones partly hidden.
2. "Summarize the open support tickets": the agent reads untrusted text and
   is tainted.
3. "Show me the API keys": refused, since a tainted agent can't read secret
   tables.
4. "Close ticket 2": held. Approve it under **Approvals**.

To try Midplane with no account, the [local
quickstart](https://github.com/midplaneai/midplane/tree/main/examples/quickstart)
runs the same sample with the policy in a file.
